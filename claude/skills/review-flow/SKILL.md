# review-flow

사용자가 지정한 **기준 이슈**에서 리뷰 범위를 찾고, Claude 내장 `/code-review`를 한 번 실행해 PR에 결과를 남긴다. 기준 이슈에 부모가 있을 필요는 없다. 사용자가 리뷰할 시점을 정하며, 개별 PR의 구현·병합 절차에 자동으로 끼워 넣지 않는다.

## 범위와 기록할 PR

- 기준 이슈의 목표·완료 조건과 연결·하위 이슈, 각각의 구현 PR을 읽는다. 같은 사용자 흐름에 속한 구현을 포함하고, 명시된 후속 작업과 무관한 연결은 구분한다. 부모 이슈나 연결 그래프 전체로 범위를 넓히지 않는다.
- 이슈 관계를 찾는 방법이 필요하면 프로젝트의 트래커 지침을 따른다. agent-loop 프로젝트는 [트래커 규칙](../../../agents/skills/agent-loop/references/tracker.md)을 참고한다.
- 관련 PR의 실제 Git 이력에서 전체 구현을 담은 head와 그 구현 전 base를 찾아 full SHA로 고정한다. 마지막 하위 PR의 diff만 고르지 않는다. 이미 머지된 구현도 포함하며, squash·rebase로 바뀐 커밋은 병합된 이력에서 확인한다.
- base가 head의 조상이고 diff가 비어 있지 않은지, 포함하기로 한 구현이 모두 들어 있는지 확인한다. 범위에 섞인 무관한 변경은 식별한다. 포함할 구현이 하나의 head에 모여 있지 않으면 부분 범위로 바꾸기 전에 확인한다.
- 기록할 PR은 사용자 지정이 있으면 우선하고, 없으면 해당 흐름의 통합 PR을 고른다. 통합 PR이 없고 기록 위치가 모호하면 관련 PR 후보를 보여 주고 정한다. 기록할 PR이 없으면 실행 전에 알리며 기록용 PR을 새로 만들지는 않는다.

조회로 결정할 수 있는 부분은 진행하고, 흐름의 경계나 기록 위치를 결정할 근거가 부족할 때만 묻는다. 실행 전에 기준 이슈·포함한 이슈와 PR·고정 범위·기록할 PR을 짧게 알린다. 범위가 명확하면 추가 승인 없이 이어간다.

## 내장 리뷰 실행

내장 `/code-review`는 Skill 도구로 호출하지 않고, **`claude -p`의 프롬프트로 전달한다.** 같은 이름의 사용자·플러그인 스킬로 대체하지 않는다.

리뷰하는 checkout은 고정한 head와 맞고 실행 중 바뀌지 않아야 한다. 로컬 작업이 있거나 같은 checkout에서 작업이 이어지고 있으면 보존한 채 별도 worktree를 사용한다.

새 CLI 세션은 현재 대화를 이어받지 않는다. 기준 이슈의 완료 조건, 포함한 이슈·PR, 의도적으로 남긴 후속 범위, 기존 검증 결과를 소스 트리 밖 임시 파일에 정리한다. 링크만 넘기지 말고 판단에 필요한 내용을 담는다.

`review_prompt`에는 `/code-review [effort] <base-sha>...<head-sha>`, `review_context_file`에는 위 파일의 절대 경로를 설정하고 리뷰 checkout에서 실행한다.

```sh
claude -p "$review_prompt" \
  --append-system-prompt-file "$review_context_file" \
  --output-format text </dev/null
```

- effort는 사용자가 지정했을 때만 넣는다. 별도 클라우드 실행인 `ultra`와 수정·게시 옵션인 `--fix`·`--comment`는 사용하지 않는다. 범위 뒤의 설명도 리뷰 대상으로 읽히므로 문맥은 임시 파일로만 전달한다.
- CLI가 종료될 때까지 같은 실행을 기다리고 종료 상태와 실제 리뷰 결과를 확인한다. 실행 실패·중단을 지적 없음으로 기록하지 않으며 자동 재실행하지 않는다. 인증·설정·권한으로 막혔다면 원인을 알린다.
- 종료 후 checkout이 달라졌는지 확인하고, 바뀌었다면 결과의 한계를 밝힌다. 결과는 PR 기록이 끝날 때까지 보존한다. 전체 흐름의 실제 동작 검증이 남았다면 리뷰 결과와 별도로 표시한다.

내장 명령의 동작이 달라졌을 때는 [공식 문서](https://code.claude.com/docs/en/code-review#review-a-diff-locally)를 확인한다.

## 지적 판단과 PR 기록

결과를 받은 뒤 지적의 근거를 코드·기준 이슈·기존 결정과 대조한다. 후속 범위의 작업을 현재 구현 누락으로 오인했는지 확인하되, 현재 흐름의 실제 실패를 후속 작업이라는 이유로 제외하지 않는다.

기록할 PR에 한국어 코멘트 하나로 다음을 남긴다. 기록한 PR의 diff와 실제 리뷰 범위가 다르면 분명히 밝힌다.

- 기준 이슈, 포함한 이슈·PR, 리뷰한 base·head와 실행 완료 여부.
- 각 지적의 위치·실패 상황·판단 근거. 조치 필요·기각·보류를 구분하고, 이미 수정한 경우에만 반영했다고 쓴다.
- 보류한 항목의 필요한 결정, 후속 이슈나 수정 PR이 있으면 그 링크.
- 기존 검증 근거와 전체 흐름에서 아직 확인하지 못한 동작. 리뷰 지적 0건을 검증 완료로 바꾸지 않는다.

멘션 없는 개발 기록으로 게시하며, 팀원을 태그해 결정을 요청할 글은 프로젝트 지침에 따라 별도 승인을 받는다. 게시 후 코멘트 내용과 링크를 확인해야 완료다. 게시만 실패했으면 결과를 보존해 게시를 이어가며 리뷰를 다시 실행하지 않는다. 중단된 작업을 이어갈 때는 같은 결과를 중복 게시하지 않는다.

기본 작업은 리뷰와 기록까지다. 사용자가 수정도 요청했다면 [implement](../../../agents/skills/implement/SKILL.md)의 구현·검증 절차로 이어가고 같은 코멘트에 실제 처리 결과를 갱신한다. 수정 후 리뷰를 자동으로 다시 돌리지 않는다. 이슈 상태·완료 조건 체크박스는 바꾸지 않는다.

마지막에는 PR 코멘트 링크와 남은 조치·결정만 짧게 보고한다.
