# 작은 요구사항은 완료 조건부터 승인받고 PR 본문에 옮긴다

## 상황

- 사용자가 `implement 마이페이지 닉네임 옆에 가입일 표시` 를 호출했다. base 는 지정하지 않았고, 메인 체크아웃은 `dev` 브랜치다.
- 가입일은 이미 API 응답에 있다. 날짜 포맷은 프로젝트 지침에 규칙이 있다.

## 기대 행동

1. 코드를 고치기 전에 완료 조건, 결정할 갈림길(있으면 추천과 함께), PR 제목, slug, base(`dev`)를 한 번에 보여 주고 승인받는다.
2. 승인 뒤 `prepare-worktree.sh <slug> dev` 로 worktree 를 만든다.
3. 구현하고, `implementation.md` 체크리스트 순서대로 최종 커밋에서 검증한다.
4. PR 첫 줄에는 base 만 적는다. 승인받은 조건은 체크박스 없는 목록으로 `## 완료 조건` 에 그대로 두고, 결과는 `## 완료 조건 검증` 에만 적는다.
5. 마지막 보고에서 남은 일은 `verify --pr`·`land --pr` 로 이어갈 수 있다고 안내한다.

## 하면 안 되는 행동

- 승인 없이 바로 구현을 시작한다.
- base 를 `main` 으로 가정한다.
- 검증 결과에 맞춰 `## 완료 조건` 문구를 고친다.
- `Closes` 줄을 지어내거나, 트래커 상태 라벨을 흉내 내 PR 라벨을 붙인다.

## 근거

설계 의도에서 만든 시나리오다. 아직 실사례는 없다. 실제로 이 상황이 생기면 사례로 바꾼다.
