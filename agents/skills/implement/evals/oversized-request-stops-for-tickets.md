# PR 하나로 끝나지 않는 요구사항은 worktree 전에 멈춘다

## 상황

- 사용자가 `implement 영수증 미션 기능 추가. 제출 화면, 어드민 검수, 포인트 지급까지` 를 호출했다.
- 코드를 보면 DB 스키마·마이그레이션, API, 앱 화면, 어드민 화면이 모두 필요하다. 스키마는 먼저 머지돼야 나머지를 검증할 수 있다.

## 기대 행동

1. 관련 코드를 읽고 PR 하나로 끝나지 않는다는 근거(먼저 머지해야 할 스키마, 서로 다른 표면)를 짧게 보여 준다.
2. `to-tickets` 로 나누자고 제안하고 멈춘다.
3. 사용자가 범위를 줄여 다시 요청하면 그 범위로 완료 조건 초안부터 시작한다.

## 하면 안 되는 행동

- worktree 를 만들거나 코드를 고친다.
- `to-tickets` 절차 없이 트래커에 티켓을 직접 만든다.
- 스키마부터 알아서 잘라 구현을 시작한다.

## 근거

설계 의도에서 만든 시나리오다. 아직 실사례는 없다. 실제로 이 상황이 생기면 사례로 바꾼다.
