# verify

아직 확인하지 못한 조건을 검증하거나, 코드·환경이 달라진 결과를 다시 확인한다. `implement`가 필요한 검증을 이미 마쳤다면 이 스킬을 따로 부를 필요는 없다. 그대로 쓸 수 있는 기존 결과는 재사용한다.

시작할 때 [공유 규칙](../agent-loop/CONTRACT.md)과 [검증과 기록 방법](../agent-loop/references/verification.md)을 읽는다. 앱 실행·조작 방법과 완료 조건별로 남길 기록물은 저장소의 프로젝트 검증 스킬(`.agents/skills/verify-<app>/`)을 따른다. 제품 코드, 티켓 상태, 이슈의 체크박스는 바꾸지 않는다. PR 생성, 커밋, push, 머지도 하지 않는다.

## 확인할 대상 정하기

| 호출 | 확인할 조건과 코드 |
|---|---|
| `verify <N>` | 티켓의 완료 조건과 연결된 열린 PR |
| `verify --pr <PR>` | PR 본문의 `Fixes`·`Closes`로 연결된 티켓의 조건. 연결된 티켓이 없으면 PR에 적힌 검증 항목 |
| `verify` | 현재 diff와 사용자 요청. 조건이 명확하면 진행하고, 뜻을 새로 정해야 할 때만 확인 |

- `--base <ref>`: 비교할 코드를 지정한다. 기본은 PR의 base이며 `main`이라고 가정하지 않는다.
- `--no-before`: 변경 전 코드와 비교하지 않는다. head의 검증 기록물은 남기고, 비교를 생략한 이유와 범위를 적는다.
- `--app`: 확인할 앱이나 API 범위를 지정한다.
- `--no-publish`: PR을 고치지 않고 로컬 결과만 보고한다.

열린 PR이 없으면 실제 로컬 커밋 SHA로 결과를 보고한다. 새 PR은 만들지 않는다.

## 검증하고 결과 남기기

- 해당 worktree에서 검증한다. 커밋하지 않은 제품 코드 변경이나 다른 작업이 있으면 덮어쓰지 않는다.
- [verified-head.sh](../agent-loop/scripts/verified-head.sh)로 기록한 커밋과 PR head를 비교한다. [검증과 기록 방법](../agent-loop/references/verification.md)의 재사용 기준에 따라 다시 확인할 조건을 고른다.
- 검증 준비나 실행이 막혀도 영향을 받지 않는 조건은 계속 확인한다. 제품 버그는 재현 방법과 실제 실패 결과를 남긴다. 검증을 통과시키려고 제품 코드를 고치지 않는다.
- 계속 사용할 검증 파일과 저장소 설정·의존성 변경은 구현 작업에서 PR에 반영한다. 이 스킬에서 만든 파일은 임시 디렉터리나 이미 gitignore로 제외된 결과 폴더에 둔다.
- 실행 후 코드와 PR head를 다시 확인하고 같은 검증 섹션을 갱신한다. 코드나 커밋이 바뀌었다면 이전 실행으로 그 변경까지 확인했다고 쓰지 않는다.

## 결과 보고와 정리

각 완료 조건의 결과와 근거·기록물을 남기고, 사용한 코드와 환경도 밝힌다. 실행하거나 기록·전달하지 못한 부분도 적는다. 자신이 시작한 서버·녹화·임시 worktree만 정리하고 전달한 기록물은 보존한다. 수정할 항목은 `implement`로 이어갈 수 있게 재현 방법과, 헤맨 진입 경로나 식별자가 없던 요소를 남긴다.
