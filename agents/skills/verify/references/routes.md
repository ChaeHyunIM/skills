# 조건별 검증 방법

완료 조건에 맞춰 아래 기준으로 검증한다. `implement`와 `verify`가 함께 사용하며 판정·코드 확인·재사용은 [공통 검증 규칙](../../agent-loop/references/verification.md)을 따른다.

| 확인할 조건 | 방법 | 필수 근거 |
|---|---|---|
| 도메인 로직·서버·순수 함수 | 프로젝트의 기존 테스트 실행 | 어떤 조건을 검사했는지, 테스트 입력과 실행 결과 |
| API 응답·데이터 저장 | 로컬·개발 API에 요청 | 요청과 응답, 필요하면 저장된 데이터. 호출 대상과 권한도 확인 |
| 새 화면 | 실제 사용자 진입 경로로 열고 사용 | head 화면 캡처 + 진입 → 주요 조작 → 목적 달성 영상 |
| 기존 화면 변경 | 같은 조건에서 base/head 실행 | 변경 전후 캡처 쌍 |
| 사용자 흐름 추가·변경, 전환·재진입·시간에 따른 동작 | 브라우저·기기에서 실제 흐름 실행 | head의 진입 → 주요 조작 → 결과가 이어지는 영상 |
| 사람이 적용해야 하는 마이그레이션 | 적용한 뒤 해당 환경에서 검사 | 적용 전에는 미검증으로 적고 사람이 해야 할 작업을 남김 |

## 테스트와 API로 확인하기

- doko 테스트는 `pnpm test <path>`로 실행한다. 이 명령이 테스트 DB를 준비하므로 vitest를 직접 실행하지 않는다.
- 기존 테스트가 해당 조건을 직접 확인하면 재사용한다. 새 테스트는 같은 문제가 다시 생길 위험과 반복 확인할 가치를 보고 작성한다. `verify`에서 새로 만들면 임시 테스트 환경에 두고 제품 코드는 고치지 않는다.
- DB 제약, 중복 처리, cascade는 사용이 허용된 실제 테스트 DB에서 확인한다. 스키마를 읽는 것만으로 충족 처리하지 않는다.
- API 요청은 입력과 응답의 status·body를 남긴다. 저장되는 조건이라면 DB의 해당 행도 읽어서 확인한다. 접속 대상과 DB 쓰기는 프로젝트 지침을 따른다. 쿠키나 토큰을 근거에 노출하지 않는다.

## UI와 변경 전후 비교

- 여러 유형에 해당하면 필요한 기록물을 함께 남긴다. 예: 기존 화면에 배송지 추가 버튼 → 기존 화면 전후 캡처 + 새 화면 캡처 + 진입·입력·저장·결과 반영 영상.
- 흐름 범위는 이번 완료 조건의 실제 진입점부터 결과까지다. 조건에 포함된 오류·취소·재진입도 확인한다. 진입 경로가 검증 대상이면 화면 URL·deep link 직행으로 대체하지 않는다.
- base/head는 화면 크기·스크롤·테마·계정·데이터를 맞추고 비교한 SHA를 기록한다. 새 화면은 head를 기록하며, 기존 진입 화면의 변경은 전후 비교한다.
- `--no-before`는 base 비교만 생략하고 이유와 범위를 적는다. 그 외 필수 비교가 막히면 확보한 head 기록물과 남은 비교를 보고한다.
- base 영상은 사용자가 요청했거나 시간에 따른 동작의 전후 비교에 필요할 때 추가한다. 서버·순수 로직만 바뀐 작업은 테스트·API 근거로 확인한다.
- 데이터 저장·권한·중복 방지는 테스트·API 근거도 확인한다. 접근성 트리는 요소 탐색·조작에 사용하고 배치·시각 상태는 캡처로 확인한다.
- base에서도 조건을 만족하면 그대로 적는다. 사용자에게 보이는 결과를 유지하는 내부 리팩터링이라면 화면에 차이가 있어야 한다고 요구하지 않는다.
- 캡처·녹화나 반복 실행 방법은 [web](web-playwright.md)·[앱](app-argent.md)을 참고한다. 도구·촬영 순서·길이는 조건에 맞게 정하며, 직접 조작도 허용한다. 반복 실행할 spec·flow는 재사용 가치가 있을 때 만든다.

## 실패했을 때

- 실행은 정상이지만 약속한 결과가 나오지 않으면 미충족이다. 시간 초과도 기능에서 약속한 시간을 어긴 것인지, 도구나 환경 때문에 실행하지 못한 것인지 구분한다.
- 환경, 로그인, 도구 문제로 실행하지 못하면 실제 오류를 근거로 미검증을 남긴다. 일시적 오류의 원인을 확인했다면 제한적으로 재시도할 수 있다. 통과시키려고 assertion의 조건을 느슨하게 바꾸지 않는다.
- 한 방법으로 확인하지 못해도 영향받지 않는 조건은 계속 검증한다. 다른 방법으로 충분한 근거를 얻을 수 있으면 사용하고 실제로 무엇을 확인했는지 밝힌다.
