# 검증 근거 확인

사용하려는 근거에 해당하는 항목만 확인한다. 첫 실행에 성공했다거나 캡처·영상 수가 적다는 이유만으로 다시 검증하지 않는다.

| 확인한 상황 | 처리 방법 |
|---|---|
| 로그인 화면, 다른 화면, 로딩 중인 화면을 캡처함 | 확인할 화면에 도달한 뒤 다시 보거나, 실행을 막은 문제를 적는다. |
| 오류 안내가 뜨거나 앱이 종료됨 | 요청한 동작의 실패인지 환경 문제인지 구분하고 실제 결과를 적는다. |
| 비교할 화면의 크기·스크롤·테마가 다름 | 차이를 판단해야 하는 비교라면 조건을 맞춰 다시 확인한다. |
| 변경 전후 결과가 같음 | 무엇을 바꾼 작업인지 확인한다. 기존 동작을 유지하는 변경이나 내부 리팩터링이면 정상일 수 있다. |
| 테스트 코드·head·서버·환경이 기록할 대상과 다름 | 그 결과를 현재 PR의 근거로 쓰지 말고 올바른 대상에서 확인한다. |
| assertion을 느슨하게 바꿔야 통과함 | 원래 조건을 유지하고 실패 결과나 필요한 결정을 보고한다. |
| 재시도한 뒤 통과함 | 재시도한 이유와 횟수, 불안정한 부분을 적는다. 이전 실패를 숨기지 않는다. |
| 테스트 데이터가 남음 | 정리해도 되는 테스트 데이터만 지우고, 다음 실행에 영향을 주지 않게 한다. |
| 영상이 길거나 첨부 용량을 넘음 | 필요한 구간만 남기거나 해상도를 조정한다. 영상이 필요 없으면 캡처나 실행 결과로 설명한다. |

토큰, 쿠키, 인증 query, storage-state, 환경 값, 실제 사용자를 식별할 수 있는 데이터는 게시하지 않는다. 이런 내용이 보이면 업로드하기 전에 노출 없는 새 근거를 만든다. PR 검증 마커 밖의 글까지 바뀐 본문은 게시하지 않는다.
