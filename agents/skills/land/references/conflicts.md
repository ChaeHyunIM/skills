# 충돌 해소

사용자가 지명한 PR의 기계적 충돌을 해소한다. 양쪽의 승인된 의도를 보존할 수 있어야 한다.

- hunk를 고치기 전에 양쪽 이슈 목표·정책·관련 PR 변경을 읽는다. `--ours`·`--theirs`로 한쪽 전체를 버리지 않는다.
- 배치·이름 변경 등 승인된 의도를 결합하는 데 필요한 최소 수정은 할 수 있다. 새 정책·기능을 지어내거나 살아 있는 동작을 조용히 제거하지 않는다.
- 마이그레이션 순서는 파일명·journal·관련 메타데이터를 함께 검토한다. 이미 적용된 마이그레이션을 다시 쓰지 않는다. 생성이 필요하면 프로젝트의 생성 승인 규칙을 따르고, 적용은 실행하지 않는다.
- 공통 workspace 문서의 cleaner·검사·commit 경로를 따른다. merge 상태와 메시지를 보존한다. 해소도 코드 변경이므로 검증된 이전 SHA와 같다고 보지 않는다.
- 무엇을 결합했고 버린 줄이 왜 불필요한지, 영향받는 완료 조건을 PR 해소 코멘트에 남긴다. 해소 결과·typecheck를 기능 검증으로 표현하지 않는다.

두 쪽의 의도가 양립하지 않으면 `git merge --abort`하고 `blocked`로 남긴다. 양쪽 의도와 출처, 필요한 결정을 보고한다. 팀 판단용 글은 초안을 승인받는다. 그 PR에 의존하는 항목은 건너뛰고 독립 항목은 계속한다.
