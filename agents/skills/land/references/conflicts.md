# merge 충돌 해결

사용자가 지정한 PR의 충돌 중, 양쪽에서 승인한 동작을 유지하면서 해결할 수 있는 부분을 처리한다.

- 충돌한 코드를 고치기 전에 양쪽 이슈의 목표와 정책, 관련 PR 변경을 읽는다. `--ours`·`--theirs`로 한쪽 전체를 버리지 않는다.
- 코드 위치나 이름을 맞추는 등 양쪽 변경을 합치는 데 필요한 최소 수정은 할 수 있다. 새 정책이나 기능을 만들거나 서비스 중인 동작을 조용히 없애지 않는다.
- 마이그레이션 순서는 파일명, journal, 관련 메타데이터를 함께 확인한다. 이미 적용한 마이그레이션을 다시 쓰지 않는다. 생성이 필요하면 프로젝트의 생성 승인 규칙을 따르고, 적용은 실행하지 않는다.
- 공통 [커밋 절차](../../agent-loop/references/workspace.md)에 따라 주석 정리와 검사를 마친 뒤 커밋한다. 기존 merge 상태와 메시지는 보존한다. 충돌 해결도 코드 변경이므로 이전에 검증한 SHA와 같다고 보지 않는다.
- PR 코멘트에 어떤 변경을 합쳤는지, 버린 줄이 왜 필요 없는지, 어느 완료 조건에 영향을 주는지 적는다. 충돌을 해결했거나 타입 체크가 통과했다는 사실을 기능 검증으로 쓰지 않는다.

양쪽의 동작을 함께 유지할 수 없어 사람이 선택해야 하면 `git merge --abort`하고 `blocked`로 남긴다. 양쪽에서 하려던 일과 근거, 필요한 결정을 보고한다. 팀에 결정을 요청할 글은 초안을 승인받는다. 그 PR에 의존하는 작업은 건너뛰고, 영향받지 않는 작업은 계속한다.
