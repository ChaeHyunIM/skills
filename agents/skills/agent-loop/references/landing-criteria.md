# 병합과 완료 조건

`land`가 읽는다. `implement`가 기록했는지 `verify`가 기록했는지는 머지 조건이 아니다. 최종 코드·환경에 맞는 근거와 최신 이슈 조건을 대조한다.

## 승인 범위

- `land`의 사용자 지명은 정상 병합의 승인이다. 남은 미충족·미검증 항목, stale·missing 기록, 예상하지 못한 코드·base 변경은 구체적으로 드러내고 아직 승인받지 않은 예외만 묻는다.
- 가능한 sync·검사·충돌 해소를 끝내 최종 후보를 준비한 뒤 예외를 모아 확인한다. 이미 같은 실행에서 승인된 정확한 예외를 다시 묻지 않는다.
- sync·해소로 head가 바뀌면 기록은 stale이다. 타입 체크로 기능 검증을 대체하거나 머지 커밋이라 current로 보지 않는다. 재검증은 implement 또는 verify에서 할 수 있다.
- 새로 드러난 조건이나 코드가 승인 범위를 벗어나면 그 PR의 병합을 보류하고 독립 항목은 계속한다. 큐의 앞 PR이 뒤 PR의 base를 바꿀 예정이면 그 영향과 검증 공백을 계획에 드러낸다.
- 승인된 stale 기록의 충족 항목도 이슈에서는 빈칸이다. 검증된 이전 코드와 지금 병합할 코드를 혼동하지 않는다.

## Checkbox update

머지 직전 이슈를 다시 읽고, current 기록에서 근거 있는 충족만 `[x]`로 바꾼다. 미충족·미검증·바뀐 조건·stale 기록의 항목은 `[ ]`다.

1. 조건 원문이 정확히 한 번 일치하는지 확인한다. 누락·중복·모호한 대응이면 추측하지 않는다.
2. 가능하면 정확한 부분 치환을 사용한다. 문자 외의 본문은 바꾸지 않는다. 옛 일반 불릿은 그 자리에서 체크박스로 바꿀 수 있다.
3. 저장 직전 읽은 본문에만 적용하고 저장 뒤 읽어서 체크박스 외에 변한 것이 없는지 확인한다. 정규화·다른 변경이 있으면 보고하며 자동 복원이나 오래된 배치를 재시도하지 않는다.
4. 변경이 없으면 쓰기를 생략한다. 쓰기·확인이 실패하면 그 PR을 머지하지 않는다. 이후 머지가 실패해도 증거 있는 체크 자체는 사실로 남는다.

재읽기는 동시 편집 창을 줄일 뿐 원자성을 보장하지 않는다.

## 승인된 미완료 항목 기록

미충족·미검증을 명시 승인받아 머지하면 PR과 이슈에 기록을 남긴다. PR은 조건·판정·근거·승인을, 이슈는 남은 동작과 승인 사실을 짧은 한국어로 쓴다. 팀원 멘션 없는 기록용 코멘트에는 별도 내용 승인을 요구하지 않는다.

실제로 승인되지 않은 이유·담당자·기한을 지어내지 않는다. 후속 티켓은 자동 생성하지 않는다. 필요한 티켓 발행 요청은 `to-tickets`를 통한다. 게시가 실패하면 기존 코멘트 중복을 확인하고 누락 기록만 복구한다. 머지를 다시 실행하지 않는다.
