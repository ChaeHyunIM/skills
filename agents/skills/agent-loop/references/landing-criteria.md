# 병합 전 완료 조건 확인

`land`에서 읽는 규칙이다. 검증을 `implement`에서 했는지 `verify`에서 했는지는 머지 조건이 아니다. 최종 코드와 환경에 맞는 검증 결과가 최신 이슈의 완료 조건을 확인했는지 살핀다.

## 추가로 승인받아야 하는 경우

- 사용자가 `land`에서 PR을 지정했으면 요청대로 병합하는 일은 승인된 것이다. 남은 미충족·미검증 조건, `stale`·`missing` 기록, 예상 밖 코드나 base 변경이 있으면 구체적으로 설명하고 아직 승인받지 않은 부분만 묻는다.
- 원격 변경 반영, 검사, 해결 가능한 충돌 처리를 마쳐 실제 병합할 코드를 준비한 뒤 확인받는다. 같은 실행에서 같은 예외를 이미 승인받았으면 다시 묻지 않는다.
- base 반영이나 충돌 해결로 head가 바뀌면 기존 기록은 `stale`이다. 타입 체크로 기능 검증을 대신하거나 merge 커밋이라는 이유로 `current`로 보지 않는다. 다시 검증하려면 `implement` 또는 `verify`로 진행할 수 있다.
- 새로 발견한 조건이나 코드가 승인받은 내용에 없으면 그 PR은 보류하고 영향받지 않는 PR은 계속 처리한다. 앞 PR을 머지하면 뒤 PR의 base가 바뀌는 경우, 그 영향과 다시 확인해야 할 부분을 계획에 적는다.
- 사용자가 `stale` 기록으로 머지하도록 승인했어도 이슈의 완료 조건은 체크하지 않는다. 이전에 검증한 코드와 지금 병합할 코드를 구분한다.

## 이슈의 체크박스 바꾸기

머지 직전에 이슈를 다시 읽는다. `current` 기록에서 근거로 확인한 충족 항목만 `[x]`로 바꾼다. 미충족·미검증, 바뀐 조건, `stale` 기록의 항목은 `[ ]`로 둔다.

1. 완료 조건 원문이 정확히 한 번 일치하는지 확인한다. 빠지거나 중복됐거나 어떤 항목인지 불분명하면 추측하지 않는다.
2. 가능하면 정확히 일치하는 부분만 바꾼다. 체크박스 문자 외의 본문은 그대로 둔다. 옛 일반 목록은 그 자리에서 체크박스 목록으로 바꿀 수 있다.
3. 저장 직전에 읽은 본문에 적용하고, 저장한 뒤 체크박스 외에 달라진 것이 없는지 확인한다. 도구가 본문 형식을 바꿨거나 다른 변경이 생겼으면 보고한다. 자동으로 복원하거나 이전 편집 내용을 그대로 다시 보내지 않는다.
4. 바꿀 것이 없으면 저장하지 않는다. 저장하거나 결과를 확인하지 못하면 그 PR을 머지하지 않는다. 체크한 뒤 머지가 실패해도 근거로 확인한 완료 표시는 사실이므로 남긴다.

저장 직전에 다시 읽어도 다른 사람이 그 사이에 본문을 바꿀 수 있다. 다시 읽는 것만으로 동시 편집을 완전히 막았다고 보지 않는다.

## 미완료 항목이 남은 채 머지한 경우

남은 항목을 이슈 코멘트로 남긴다. 머지 뒤에 누군가 이어서 확인할 일이다. 멘션 없는 기록이라 따로 승인받지 않는다.

- 쓰는 것: 항목마다 무엇을, 언제·어디서 확인하면 되는지. 머지 전에 해결된 항목은 뺀다.
- 쓰지 않는 것: 머지 방식, SHA, rebase·squash 경위, 승인받은 사실. PR과 트래커의 PR 연동으로 알 수 있다.
- PR에는 머지 기록 코멘트를 달지 않는다. 머지 경위는 사용자 보고에만 적는다.
- 이유·담당자·기한을 지어내지 않는다. 후속 티켓은 요청받았을 때만 `to-tickets`로 만든다.
- 게시에 실패하면 중복을 확인하고 빠진 것만 보완한다. 머지는 다시 하지 않는다.

```markdown
머지 후 확인이 남은 항목

- [ ] 지정 시각에 3개 캐러셀이 갱신된다 — 배포 뒤 어드민에서 자동 편성을 켜고, 첫 00:00(한국시간) 실행에서 확인
```
