# 검증과 하나의 PR 기록

`implement`와 `verify`가 공유한다. 라운드와 `land`는 기록을 읽고, 자기 작업을 이유로 검증 결과를 승격하지 않는다.

## 증거와 대상

- 이슈의 `## 완료 조건`을 한정어까지 그대로 읽는다. `Acceptance criteria`·`검수 기준`은 옛 제목으로 읽는다. 조건이 바뀌거나 추가됐으면 이전 기록으로 추정 통과시키지 않는다.
- 판정은 `충족`(전체 조건을 확인한 근거), `미충족`(실제 실패 결과), `미검증`(근거 부족·환경 장애·낡은 근거)이다. 타입 체크와 clean review는 런타임 동작의 증거가 아니다.
- 실제로 조건을 확인한 기존 테스트·요청·화면 관찰은 재사용한다. 재사용할 코드·검사 입력·의존성·환경이 유효한지 확인한다. 검사를 새로 돌렸다고 쓰지 않는다.
- 검사 전 통과 기준을 이해하고 필요한 관찰을 정한다. 고정 문장 형식·매체 개수는 요구하지 않는다. 조건에 맞는 경로는 `verify/references/routes.md`에서 읽는다.
- 최종 기록 대상은 **full PR head SHA**다. 실행 전후 clean worktree와 head를 `agent-loop/scripts/check-worktree.sh <worktree> <expected-head>`로 확인한다. 서버·기기·API가 그 소스와 환경을 실제로 사용했는지도 확인한다.
- `implement`는 제품 코드와 새 테스트를 커밋한 최종 head에서 검증한다. 커밋 전 실행 결과는 실행 당시의 소스·테스트·의존성 입력이 최종 커밋과 동일함을 확인한 경우에만 재사용하며 그 근거를 적는다. 테스트 뒤 바뀐 코드를 새 SHA의 증거로 바꾸지 않는다.
- `verify`는 제품 소스를 고치지 않는다. 새 검증 파일·설정은 임시 디렉터리 또는 이미 무시되는 산출물 경로에 둔다. PR에 넣을 회귀 테스트는 구현 작업으로 반영한 뒤 새 head에서 확인한다.
- 검증 중 소스나 head가 달라지면 해당 결과를 그 PR head의 근거로 게시하지 않는다. 원래 대상을 보존한 보고를 남기고 영향을 다시 확인한다.

## current와 재사용

`verify/scripts/verified-head.sh <PR> [<worktree>]`가 다음을 출력한다.

| 출력 | 의미 |
|---|---|
| `current <sha>` · exit 0 | 기록 커밋과 PR head가 정확히 같음 |
| `stale <sha> <n>` · exit 1 | 서로 다른 커밋. n은 양쪽에만 있는 커밋 수이며 “n 커밋 전”이라는 뜻이 아님 |
| `missing <이유>` · exit 2 | 기록이 없거나 모호함, SHA·원격 상태를 확인할 수 없음 |

merge·rollback·같은 파일 tree에도 SHA가 다르면 stale이다. `current`여도 항목 누락, 조건 변경, 다른 환경은 개별 평가한다.

- 같은 head에서는 요청된 항목과 낡은 환경·실패·빈틈만 확인한다. 다른 유효한 항목을 반복 실행하지 않는다.
- head가 바뀌면 항목별로 영향을 평가한다. 검사한 소스·의존성·환경이 그대로임을 구체적으로 입증한 근거는 재사용 출처와 이유를 적고, 영향을 받았거나 불명확한 조건만 다시 실행한다.
- 기록 SHA만 바꾸지 않는다. 새 head의 전체 조건에 위 판단을 마친 뒤 새 기록을 작성한다. 남은 조건은 미검증으로 두고 이전 근거의 SHA와 부족한 이유를 보존한다.

## 기록 형식과 게시

현재 기록은 PR 본문의 `## 완료 조건 검증` 하나다. `implement`는 PR 생성 시 자신의 결과를 넣고, `verify`는 같은 섹션을 갱신한다. 전부 충족이면 다음 필수 단계로 `verify`를 안내하지 않는다.

```markdown
<!-- verify:start -->
## 완료 조건 검증

검증 대상: [<full sha>](https://github.com/<owner>/<repo>/commit/<full sha>) · 환경: <실제 환경>

- [x] <완료 조건 원문> — 충족
  - 근거: <재현 방법·관찰 결과 또는 유효한 기존 근거의 출처>
- [ ] <완료 조건 원문> — 미충족
  - 결과: <기대와 실제 결과>
- [ ] <완료 조건 원문> — 미검증
  - 이유: <실제 장애 또는 남은 확인>
<!-- verify:end -->
```

`verify/scripts/evidence-block.mjs`가 `results.json`을 위 형식으로 렌더한다. 게시·매체 처리 절차는 `verify/references/publishing.md`를 필요한 경우 읽는다.

- 저장 직전에 PR head·이슈 조건·본문을 다시 읽는다. 본문이 읽은 뒤 달라졌으면 최신 본문에 다시 결합한다. 저장 후 head와 본문을 읽어 확인한다.
- 바인딩 줄과 검증 섹션 밖의 사람 글은 그대로 보존한다. 마커 밖을 정리하거나 오래된 본문 전체를 덮어쓰지 않는다. 모호한 중복 섹션이면 해당 게시를 멈춘다.
- PR이 없는 명시적 로컬 검증은 실제 로컬 SHA와 환경을 보고한다. 이를 열린 PR 검증으로 표현하지 않는다.
