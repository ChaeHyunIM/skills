# 구현하고 PR 준비하기

`implement`의 구현·검증·PR 준비 절차다. 완료 조건과 작업 폴더가 정해진 뒤부터 PR을 열고 결과를 보고하기 전까지를 다룬다. `implement-ticket`도 티켓 단계를 마친 뒤 이 절차를 그대로 따른다.

순서가 바뀌면 검증한 커밋과 PR head가 어긋나기 쉽다. 아래 목록을 작업 메모에 복사해 하나씩 체크하며 진행하고, 각 단계의 기준은 이어지는 섹션에서 확인한다.

```markdown
- [ ] 구현하고 완료 조건별 실제 동작을 확인했다
- [ ] code-quality로 고른 스킬을 적용하고 범위 안의 문제를 고쳤다
- [ ] 원격 base 최신 커밋을 반영하고 관련 검사를 다시 했다
- [ ] comment-cleaner → 필요한 검사 → commit 순서로 커밋했다
- [ ] 최종 커밋에서 검증했다(재사용한 결과는 같은 코드·입력인지 확인)
- [ ] push한 뒤 PR head가 검증한 커밋과 같고, 커밋하지 않은 변경이 없다
- [ ] PR을 열거나 갱신하고 검증 결과를 적었다
- [ ] 게시한 본문과 PR head를 다시 확인했다
```

## 구현하고 검증하기

- 목표와 완료 조건, 프로젝트 지침을 따른다. Figma 링크가 있는 UI는 해당 스킬과 도구로 디자인을 읽고 배치와 스타일을 맞춘다. 디자인과 승인된 정책이 충돌하면 그 부분을 확인받는다.
- 구현한 기능이 완료 조건을 충족하는지까지 검증한다. 실제 동작 확인을 다음 `verify` 호출로 미루지 않는다.
- [code-quality](../../code-quality/SKILL.md)로 변경에 맞는 전문 스킬을 읽고 코드 품질을 확인한다. 작업 범위 안에서 발견한 문제는 이번 구현에서 고친다.
- 진입 방법·준비 상태·함정을 찾느라 헤맸다면 프로젝트 검증 스킬의 방식대로 기능 메모에 남긴다. 문구나 좌표로만 잡힌 핵심 요소에는 안정적인 식별자를 붙인다. 둘 다 이번 PR에 포함한다. 프로젝트 검증 스킬이 없으면 새로 만들지 않는다.
- 앱 실행·조작 방법과 완료 조건별로 남길 기록물은 저장소의 프로젝트 검증 스킬을 따른다. 필수 기록물을 사람이 열어볼 수 있게 전달해야 검증이 끝난다. 유효한 기존 결과와 기록물은 재사용한다.
- 작업 범위 안에서 발견한 구현 오류는 고치고 관련 검사를 다시 한다. 회귀 테스트는 같은 문제가 다시 생길 위험과 반복 사용할 가치를 보고 추가한다.
- 확인할 수 없는 조건은 실제 환경 문제나 권한 부족을 확인한 뒤 미검증으로 남긴다. “설치 여부 미확정”처럼 확인하지 않은 추측을 이유로 쓰지 않는다. 다른 조건은 계속 확인한다.

## 최종 코드를 확인하고 PR 준비하기

다음 준비를 마친 뒤 PR을 열거나 갱신한다.

- 작업 브랜치에 원격 base의 최신 커밋을 반영하고 관련 검사를 다시 한다. 충돌은 임의로 해결하지 않고 기록한다. 로컬 base에만 있는 커밋은 대신 push하지 않고 알린다.
- [작업 환경](workspace.md)의 `comment-cleaner` → 필요한 검사 → `commit` 순서로 커밋하고 새 테스트도 포함한다.
- 최종 커밋에서 검증한다. 앞서 실행한 결과를 쓰려면 코드와 입력이 최종 커밋에서도 같은지 확인한다.
- 작업 브랜치를 push한 뒤 PR head가 검증한 커밋과 같은지, worktree에 커밋하지 않은 변경이 없는지 확인한다.

새 작업은 draft가 아닌 PR을 연다. 본문은 [PR 본문 양식](pr-body.md)을 따르고, 검증 결과는 [검증과 기록 방법](verification.md)에 있는 형식으로 적는다. 기존 PR은 최신 본문에서 에이전트가 쓴 섹션과 검증 결과만 고치고, 다른 사람이 쓴 글은 보존한다.

게시한 뒤 본문과 PR head를 다시 확인한다. 검증이 남아 있을 때만 남은 항목을 적고 `verify`로 이어갈 수 있다고 안내한다.

머지는 이 절차에서 시작하지 않는다. 진행 상황을 보여 주려고 구현 도중 PR을 먼저 열지 않는다.

## 마지막 보고

PR 링크, 실제 검증 결과와 기록물, 남은 항목과 필요한 결정을 적는다. 환경 문제로 확인하지 못한 조건은 PR과 채팅에 함께 적는다. 팀에 결정을 요청할 코멘트는 초안을 승인받고, 승인을 기다리는 동안 다른 작업은 마친다.
