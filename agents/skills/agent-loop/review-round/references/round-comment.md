# 라운드 코멘트 — 형식과 규칙

라운드가 새로 게시하는 **PR 요약 코멘트 하나**. PR 본문의 `## 완료 조건 검증` 은 `implement`·`verify`가 작성하는 현재 기록이므로 라운드는 읽고 자기 결과는 이 코멘트에 남긴다. Claude와 Codex의 원본 출력은 로컬 scratchpad에만
남고, 두 엔진의 지적을 합쳐 이 코멘트에서 반영·기각·보류로 판정한다.

채팅은 이 코멘트와 필요한 결정을 가리킨다. 보류가 있으면 이 세션에서도 결정 내용을 알 수 있게 한다.
채팅에는 필요한 결정을 짧게 옮기되 선택지·추천의 의미를 바꾸지 않는다. 팀 코멘트 게시 승인은 해당 초안을 준비한 뒤 받는다.

## 작성 규칙

- **산문이 아니라 목록.** 지적 하나에 한 줄. 사람은 이 코멘트를 훑어 *머지할지 말지* 를 정한다 —
  자기에게 온 질문을 찾으려고 이야기를 읽어야 해서는 안 된다.
- **모든 지적이 표에 한 줄씩.** 두 엔진이 같은 위치에서 같은 실패를 지적했을 때만 한 줄로
  합치고 출처를 `Claude+Codex` 로 쓴다. 비슷한 주제라도 실패 시나리오가 다르면 묶지 않는다.
  "사소해서 생략" 도 하지 않는다.
  생략하면 다음 라운드가 같은 것을 또 지적한다.
- 각 항목은 짧게 쓴다. 기술적 반영과 정책 보류는 설명 길이가 아니라 결정의 소유권으로 구분한다.
- **보류는 선택지·추천·필요한 결정 3요소가 전부 있어야 한다.** 선택지 없는 보류는 질문이 아니다.
- 보류 0건이면 섹션을 통째로 빼지 말고 `보류 없음 — 결정할 것 없다` 한 줄. 섹션이 사라지면
  사람이 "빠뜨린 건가" 를 의심한다.
- base 충돌·마이그레이션 순서 문제도 **보류 항목으로 표에 올린다.** 검증 줄에만 적으면 묻힌다.
- **지적 번호는 반드시 백틱 안에** — `` **`#1`** ``. 맨 `#1` 은 GitHub 이 저장소의 PR/이슈 1번
  링크로 치환해서, 번호 자리에 무관한 PR 제목이 박힌다. 표의 `| 1 |` 셀처럼 `#` 없는 숫자는 그대로.
- **개별 finding에 커밋 sha를 나열하지 않는다.** 라운드 변경은 반영 헤더의 compare 링크로 가리키고,
  개별 항목·기각 근거·보류 설명은 전부 `path:line` 으로 짚는다. rebase-merge 트렁크에서 sha 는
  머지 순간 갈릴 수 있다. 검증 대상 SHA는 아래 검증 줄에 별도로 기록한다. 마이그레이션 충돌 상대는 **파일명**으로 짚는다.
- `$ROUND_BASE..HEAD` 밖의 커밋은 인용하지 않는다 — 이전 라운드도, base 쪽도, 다른 PR 도.
- 완료 조건 대조에서 찾은 구현 누락은 출처를 `완료 조건`으로 쓴다. 코드가 없으면 위치에 조건 원문을
  적으며 파일·줄 번호를 만들지 않는다. 검증 근거만 부족한 항목은 지적 수를 부풀리지 않고 검증 줄에 한 줄로 적는다.
- 검증 섹션에는 이번 라운드에서 대조한 항목과 결과, 그리고 `verified-head.sh` 가 찍은 기록 상태만 적는다.
  라운드에서 수행한 검사는 그대로 기록한다. head가 달라졌으면 현재 PR 기록은 stale이며 implement·verify가 근거를 평가해 갱신한다.

## 본문 형식

섹션 순서를 유지하고, 진짜로 비어 있을 때만 뺀다.

```markdown
## 리뷰 라운드 <K>

Claude `/code-review <args> <PR>` · Codex `<실제 모델>/<effort> $review-agent` · 지적 <n>건 — 반영 <a> · 기각 <b> · 보류 <c>

### 지적 전체

| # | 출처 | 위치 | 지적 | 처리 |
|---|------|------|------|------|
| 1 | Claude | `apps/api/src/…:189` | limit 이 소수면 422 아닌 500 | ✅ 반영 |
| 2 | Codex | `…/repository.ts:35` | 홈 고정 섹션이 매 요청 전량 집계 | ⏸️ 보류 |
| 3 | Claude+Codex | `…/route.ts:44` | 중복 신청 23505 가 500 으로 샌다 | ❌ 기각 |

### 반영 — [이번 라운드 변경 <f>개 파일](https://github.com/<owner>/<repo>/compare/<ROUND_BASE>..<ROUND_HEAD>)

- **`#1`** `[Claude]` `path:line` — <무엇이 깨졌나> → <무엇을 바꿨나>

### 기각

- **`#3`** `[Claude+Codex]` `path:line` — <왜 사실이 아닌가> (근거: `path:line`)

### 보류 — 결정 필요

- **`#2`** `[Codex]` `path:line` — <문제 한 줄>
  - 안 고친 이유: <마이그레이션 필요 / 판단 갈림 / 규칙상 사람 몫>
  - 선택지: ⓐ <현행 유지> ⓑ <…> ⓒ <…>
  - 추천: ⓑ — <한 줄 근거>
  - **필요한 결정: ⓐ~ⓒ 중 택 1**

### 리뷰 범위와 한계

- Claude: <항목> · <항목>
- Codex: <항목> · <항목>

### 검증

- 리뷰 기준: Claude `<ROUND_BASE>` · Codex `<ROUND_BASE>`
- `pnpm check-types:<app>`: <결과>
- 완료 조건: <이번 라운드에서 대조한 항목과 결과>
- 검증 기록: `<current sha | stale sha n | missing>` — stale·missing이면 재검증 또는 해당 공백의 명시적 머지 승인 필요
- base 병합: <충돌 0 / 충돌 내용> · 마이그레이션: <없음 / 순서 주의>
```

## 상황별 추가 줄

- **Claude 원본 지적이 32건 정확히** → Claude 목록이 잘렸다. 헤더 줄에
  `Claude 스키마 상한 32건에 걸림 — 전체가 아님` 을 붙인다.
- **Claude가 산문 폴백으로 돌았을 때** → 헤더 줄에
  `degraded — Claude 구조체 출력 없이 산문 파싱` 을 붙인다. Codex는 구조체 출력이 아니면
  라운드를 실패시키므로 산문 폴백이 없다.
- **이번 라운드 커밋이 없을 때** → `### 반영 — 커밋 없음`, compare 링크 없음.
  보여줄 것을 만들려고 이전 라운드 커밋을 끌어오지 않는다.
