# PR에 리뷰 결과 적기

이번 라운드의 결과는 PR 요약 코멘트 하나에 적는다. PR 본문의 `## 완료 조건 검증`은 `implement`·`verify`가 갱신하는 기록이므로 리뷰에서는 읽기만 한다. Claude와 Codex의 원본 출력은 로컬 임시 폴더에 남기고, 두 결과를 모아 반영·기각·보류로 정리한다.

채팅에는 이 코멘트의 링크와 필요한 결정을 알린다. 보류한 항목은 채팅에서도 무슨 결정이 필요한지 설명하되, PR에 적은 선택지와 추천의 뜻을 바꾸지 않는다. 팀에 올릴 코멘트는 초안을 준비한 뒤 승인받는다.

## 작성 기준

- 지적은 목록과 표로 짧게 쓴다. 사람이 훑어보며 머지할지 판단하고 자기에게 온 질문을 찾을 수 있어야 한다.
- 모든 지적을 표에 한 줄씩 넣는다. 두 리뷰어가 같은 위치에서 같은 실패를 지적했을 때만 합치고 출처를 `Claude+Codex`로 쓴다. 주제가 비슷해도 실패 상황이 다르면 따로 남긴다. 사소해 보인다고 빼면 다음 라운드에서 같은 내용을 다시 지적할 수 있다.
- 항목마다 설명은 짧게 쓴다. 개발자가 고칠지 사람이 결정할지에 따라 처리하며, 설명이 길다는 이유만으로 정책 보류로 분류하지 않는다.
- 보류한 항목에는 선택지, 추천, 필요한 결정을 모두 적는다. 선택지 없는 보류로 질문을 대신하지 않는다.
- 보류가 0건이면 `보류 없음 — 결정할 것 없다`라고 한 줄 남긴다. 섹션이 없어서 빠뜨렸는지 의심하게 만들지 않는다. base 충돌과 마이그레이션 순서 문제도 검증 줄에만 적지 말고 보류 표에 올린다.
- 지적 번호에 `#`을 붙일 때는 `` **`#1`** ``처럼 백틱으로 감싼다. 그렇지 않으면 GitHub가 무관한 PR·이슈 링크로 바꾼다. 표의 `| 1 |`처럼 `#` 없는 숫자는 그대로 쓴다.
- 지적마다 커밋 SHA를 나열하지 않는다. 라운드 전체 변경은 반영 제목의 compare 링크로 연결하고, 개별 항목의 위치와 근거는 `path:line`으로 적는다. rebase 방식으로 머지하면 SHA가 바뀔 수 있다. 검증한 SHA는 검증 줄에 따로 적고, 충돌한 마이그레이션은 파일명으로 짚는다.
- `$ROUND_BASE..HEAD` 밖의 커밋은 인용하지 않는다. 이전 라운드, base, 다른 PR의 커밋도 포함하지 않는다.
- 완료 조건을 확인하다 찾은 구현 누락은 출처를 `완료 조건`으로 쓴다. 코드가 없으면 위치 대신 조건 원문을 적고 파일·줄 번호를 만들지 않는다. 검증 근거만 부족한 항목은 지적 수에 더하지 않고 검증 줄에 적는다.
- 검증 섹션에는 이번 라운드에서 확인한 항목과 결과, 실행한 검사, `verified-head.sh`가 출력한 기록 상태를 적는다. head가 달라졌으면 기록은 `stale`이며 `implement`·`verify`가 근거를 확인해 갱신한다.

## 코멘트 형식

아래 섹션 순서를 유지한다. 내용이 없는 섹션만 생략할 수 있으며, 보류 섹션은 위 규칙대로 0건이어도 남긴다.

```markdown
## 리뷰 라운드 <K>

Claude `/code-review <args> <PR>` · Codex `<실제 모델>/<effort> $review-agent` · 지적 <n>건 — 반영 <a> · 기각 <b> · 보류 <c>

### 지적 전체

| # | 출처 | 위치 | 지적 | 처리 |
|---|------|------|------|------|
| 1 | Claude | `apps/api/src/…:189` | limit에 소수를 넣으면 422 대신 500을 반환함 | ✅ 반영 |
| 2 | Codex | `…/repository.ts:35` | 홈 고정 섹션을 요청할 때마다 전체 데이터를 집계함 | ⏸️ 보류 |
| 3 | Claude+Codex | `…/route.ts:44` | 중복 신청 오류(23505)가 500 응답으로 반환됨 | ❌ 기각 |

### 반영 — [이번 라운드 변경 <f>개 파일](https://github.com/<owner>/<repo>/compare/<ROUND_BASE>..<ROUND_HEAD>)

- **`#1`** `[Claude]` `path:line` — <어떤 문제가 있었는지> → <무엇을 고쳤는지>

### 기각

- **`#3`** `[Claude+Codex]` `path:line` — <지적이 사실과 다른 이유> (근거: `path:line`)

### 보류 — 결정 필요

- **`#2`** `[Codex]` `path:line` — <문제 한 줄>
  - 안 고친 이유: <마이그레이션 필요 / 판단 갈림 / 사람이 결정할 규칙>
  - 선택지: ⓐ <현행 유지> ⓑ <…> ⓒ <…>
  - 추천: ⓑ — <이유 한 줄>
  - **필요한 결정: ⓐ~ⓒ 중 택 1**

### 리뷰 범위와 한계

- Claude: <항목> · <항목>
- Codex: <항목> · <항목>

### 검증

- 리뷰 기준: Claude `<ROUND_BASE>` · Codex `<ROUND_BASE>`
- `pnpm check-types:<app>`: <결과>
- 완료 조건: <이번 라운드에서 확인한 항목과 결과>
- 검증 기록: `<current sha | stale sha n | missing>` — stale·missing이면 다시 검증하거나 어떤 확인이 빠졌는지 설명하고 머지 승인을 받아야 함
- base 병합: <충돌 0 / 충돌 내용> · 마이그레이션: <없음 / 순서 주의>
```

## 필요한 경우 덧붙일 내용

- Claude의 원본 지적이 정확히 32건이면 결과가 상한에 걸려 잘린 것이다. 첫 요약 줄에 `Claude 지적이 최대 32건 제한에 걸림 — 전체 결과가 아닐 수 있음`을 붙인다.
- Claude가 정해진 형식으로 출력하지 않아 일반 텍스트에서 지적을 추출했으면 `degraded — Claude의 일반 텍스트에서 지적 추출`이라고 표시한다. Codex는 정해진 형식의 결과가 없으면 라운드 실패로 처리한다.
- 이번 라운드에서 커밋하지 않았으면 `### 반영 — 커밋 없음`으로 적고 compare 링크를 넣지 않는다. 보여 줄 변경을 만들려고 이전 라운드 커밋을 가져오지 않는다.
