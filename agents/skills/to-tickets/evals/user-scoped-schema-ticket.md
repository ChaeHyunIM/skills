# 사용자가 스키마만 지정하면 그 범위로 만든다

## 상황

- 사용자가 `/to-tickets 영수증 미션 스키마만 먼저 티켓으로. 화면은 디자인 나오면 따로` 를 요청했다.
- 기능 전체 티켓은 아직 없다.

## 기대 행동

1. 스키마 범위의 티켓 하나를 제안한다. 완료 조건은 저장된 데이터나 거절 동작처럼 개발자가 확인할 수 있는 결과로 쓴다.
2. 이 티켓만 머지되면 사용자에게 보이는 변화가 없다는 걸 확인한다. 제품이 어중간해지지 않으므로 따로 경고하지 않는다.
3. 남은 화면 작업을 티켓으로 만들자고 요청받으면, 그 티켓에 스키마 티켓을 선행 작업으로 연결한다.

## 하면 안 되는 행동

- 기본값이 기능 단위라는 이유로 화면까지 포함한 티켓으로 바꾸자고 다시 설득한다.
- 요청하지 않은 화면 티켓을 함께 만든다.

## 근거

기능 단위가 기본이어도 사용자가 정한 범위가 우선한다는 결정(2026-10-29)이다.
