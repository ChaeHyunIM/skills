# Commit

현재 저장소의 지침과 변경 범위를 확인한 뒤 하나의 응집된 커밋을 만듭니다.

## 범위

- 사용자가 현재 작업의 커밋을 명시적으로 요청했을 때만 실행합니다.
- 로컬 커밋만 만듭니다. 사용자가 따로 요청하지 않은 push, amend, reset, rebase는 하지 않습니다.
- 적용되는 `AGENTS.md`의 커밋 전 검사와 저장소 규칙을 먼저 따릅니다.

## 변경 검토

1. `git status --short`, staged·unstaged diff, 현재 브랜치, 최근 커밋을 확인합니다.
2. 이번 작업과 무관하거나 사용자가 먼저 만든 변경은 보존합니다. 포함 여부를 안전하게 판단할 수 없으면 커밋 전에 사용자에게 묻습니다.
3. 검사 실패가 남아 있으면 원인을 보고하고, 실패한 상태로 커밋해도 된다는 명시적 요청 없이는 커밋하지 않습니다.

## 커밋 생성

1. 이번 작업에 해당하는 파일만 스테이징합니다. 다른 staged 변경이 있으면 커밋 범위에 포함되는지 확인합니다.
2. 서로 분리할 이유가 없는 하나의 응집된 커밋을 만듭니다.
3. 커밋 제목은 한국어 Conventional Commits 형식으로 작성합니다.
   - 형식: `type(scope): description`; scope가 불필요하면 `type: description`
   - type: `feat`, `fix`, `refactor`, `style`, `chore`, `docs`, `test` 등 변경 성격에 맞는 값
   - scope: 저장소에서 사용하는 소유 영역이나 패키지 이름
   - description: 명령형 한국어로 쓰고 `~함`으로 끝냅니다.
4. 대화형 편집기를 열지 않고 한 번의 `git commit`으로 커밋합니다.

## 완료 확인

- 새 커밋의 해시와 제목을 확인합니다.
- `git status --short`를 다시 확인하고, 커밋하지 않고 남긴 변경이 있으면 사용자에게 알립니다.
